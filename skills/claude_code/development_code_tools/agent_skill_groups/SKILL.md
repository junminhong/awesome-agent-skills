# Agent Skill Groups

**Platforms:** Claude Code, Codex, OpenCode, generic SKILL.md layouts
**Tags:** skill-management, profile-switching, cli, agent-skills
**Use cases:** Use when a local agent setup has many installed skills and should load only the skills needed for the current scenario.

## Objective

Organize a large local `SKILL.md` library into scenario groups, keep a small
baseline profile active, and switch specialized groups on demand without editing
the original skill contents.

## Inputs

- **Runtime:** One of `codex`, `claude-code`, `opencode`, or `generic`.
- **Skill roots:** Existing active skill directories and a managed disabled pool.
- **groups.json:** The grouping table generated by `init` or maintained by the user.

## Outputs

- A validated skill inventory and suggested groups.
- A reversible profile switch plan.
- A backup manifest before moving skill directories.
- A managed `AGENTS.md` or `CLAUDE.md` instruction block via `memory --write`.

## Workflow

1. Install or clone <https://github.com/go165/agent-skill-groups>.
2. Inspect supported runtimes with `agent-skill-groups runtimes`.
3. Generate a first config with `agent-skill-groups init --runtime claude-code --output groups.json`.
4. Review suggestions with `agent-skill-groups status --config groups.json --runtime claude-code --details`.
5. Preview changes with `agent-skill-groups plan --config groups.json --runtime claude-code <group>`.
6. Persist agent instructions with `agent-skill-groups memory --config groups.json --runtime claude-code --write CLAUDE.md`.
7. Back up before moving directories with `agent-skill-groups backup --config groups.json --runtime claude-code`.
8. Switch profiles with `agent-skill-groups profile --config groups.json --runtime claude-code <group>`.
9. Return to the small baseline with `agent-skill-groups profile --config groups.json --runtime claude-code core`.

## Constraints & Guardrails

- Do not delete skill directories as part of grouping.
- Do not edit third-party `SKILL.md` contents during profile switching.
- Keep protected baseline skills in `core`.
- Run `plan` and `backup` before `profile` on an existing workstation.
- Restart or reload the agent runtime after changing the active skill filesystem.

## Example

```bash
pipx install git+https://github.com/go165/agent-skill-groups.git
agent-skill-groups init --runtime claude-code --output groups.json
agent-skill-groups memory --config groups.json --runtime claude-code --write CLAUDE.md
agent-skill-groups plan --config groups.json --runtime claude-code research
agent-skill-groups backup --config groups.json --runtime claude-code
agent-skill-groups profile --config groups.json --runtime claude-code research
```

## Evaluation Checklist

- [ ] `agent-skill-groups validate --config groups.json --runtime claude-code` reports no unexpected missing or malformed skills.
- [ ] `plan` shows the intended enable/disable operations before any move.
- [ ] `backup` writes a restore manifest.
- [ ] `memory --write` updates only one managed block and preserves other instruction-file content.
- [ ] `profile core` returns the setup to the lean baseline.
